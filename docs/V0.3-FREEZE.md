## 1. 为什么要有这份清单

"bug 比功能多"的感受根源不是工程质量，而是**兼容面无边界**：每张卡的脚本、每个预设的正则都是隐式契约，任何一处不匹配都会被记为 bug。ST 自己发新版都会弄坏一批卡，100% 兼容在地球上不存在。本清单把"无限责任"切成"有限责任"：**承诺什么、尽力什么、明确不承诺什么**，让"修完了"重新成为一个可到达的状态。

## 2. 工作模式（每一轮开工前先声明自己在哪种模式）

| 模式 | 允许做 | 禁止做 | 产出要求 |
|---|---|---|---|
| **收口模式**（默认） | Tier 1 缺陷修复、验证债闭环、发布三硬门槛（§5） | 不碰 Tier 2 深水区新问题；不加新功能 | 每个 Tier 1 修复必须同时补进回归清单或测试 |
| **探索模式** | 任意深水区问题（需用户当轮明确声明进入） | —— | 产出只记 known issue（本文档 §4 或审计报告），不得阻塞发布判定 |

防"修了又冒"的两条纪律：
1. Tier 1 修复必须落回归（测试/模拟器探针/真机回归清单三选一），否则不算修复完成。
2. 同一张卡第三次冒同类问题时，强制升级为 Tier 2 时间盒议题（先修机制，不追着卡跑）。

## 3. 兼容分级（对外承诺口径）

### Tier 1 —— 承诺兼容，坏了算 bug（已基本达成，维持住）

- 数据迁移：ST 整包 data.zip、角色卡（PNG/JSON）、世界书、预设、聊天记录导入导出，聊到一半接着聊。
- 世界书触发：constant / 关键词（正则、大小写、全词）/ 副关键词 / 递归 / scanDepth / timed effects / 互斥组 / token 预算。
- 预设：ST OpenAI Settings 导入（prompts + prompt_order + regex_scripts）、条目开关、随时切换。
- 正则：三时机（display/prompt/permanent）、placement、depth、substituteRegex、三源作用域（global/preset/character）。
- MVU：`<UpdateVariable>` / `<JSONPatch>`（add/replace/remove/delta/move/copy/insert）/ `<initvar>` / `_.set` 系 / stat_data 双树合并 / 状态栏 / getvar 系宏。
- 酒馆助手基本盘：TH API 三份名单（**本地 / 桥接 / 记名拒绝**，**条数以源码为准** —— ★ **W59 修**：原写「**71 个 API（28 本地 + 43 桥接）**」，而实测 **本地 34 + 桥接 41 = 75**、记名拒绝 **81 项**，见 `P-60`）、tavern_events **82 项全表**（★ 此项**有机器守**：**vitest 规格** `packages/tests/th-script-runtime.spec.ts` 断言 `toHaveLength(82)` —— ★ **W64 修**：原写「由 `audit-card-event-surface.mjs` 断言」，而**该脚本在构建期零引用**，**它从不跑**）、事件时序、脚本管理面板。
- 交互闭环：回退 / 编辑 / 重新生成 / 变体、楼层口径（1 输入=1楼）、记忆插件、思考耗时。
- 渲染：楼层头、reasoning 折叠、代码块美化、状态栏、台词着色（ST-COMPAT-PACT A 族条款）。

### Tier 2 —— 尽力而为，坏了记 known issue（每卡/每项设时间盒）
