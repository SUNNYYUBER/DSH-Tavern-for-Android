# DSH Tavern for Android

> 项目名：**DSH Tavern for Android**（简称 **DSHTavern**）

**把你的 SillyTavern 数据（角色卡 / 世界书 / 预设 / 正则 / 聊天记录）搬进一个安卓 App。**

装上即用，全部本地运行，不上传你的任何数据。

**当前版本**：`0.2.0`（内嵌 DSH `0.1.5-rc.1`）　|　**状态**：⚠️ **Alpha（早期测试版，随时可能不可用）**

---

## ⚠️ 先读这段：它**很可能不能正常用**

**这是一个早期测试版（Alpha），不是一个「产品」。**

- **bug 会很多** —— 其中一部分**严重到功能不可用 / 数据异常 / 需要重装**
- **不要拿它当日常主力工具**，更不要用在**你无法承受丢失的数据**上
- **机型覆盖极不完整**：只在一台模拟器 + 有限真机上验证过（见下方「Alpha 限制声明」）
- 遇到问题**大概率不会立刻修**（个人业余项目，见「反馈与贡献」）

**那为什么还要公开？** 两个动机：

1. **分享思路** —— 安卓上跑起 DSH 运行时的可行路径、ST 资产迁移的兼容分层、

   这里公开的是「**我们补到哪了**」，欢迎在自己的 fork 上继续

**这是一份诚实的「半成品」，不是「可用的免费替代品」。**

# 第一部分：给使用者

## 快速开始

1. 下载并安装对应架构的 APK（`arm64` = 真机，`x86_64` = 模拟器）
2. 打开 App → **设置 → 模型** → 填入你的 API Key（DeepSeek 官方，或任意 OpenAI 兼容端点）
3. 侧栏底部「🎭 角色扮演」→「导入」页，选一种导入方式：

   | 导入方式 | 用途 |
   |---|---|
   | 📦 **完整数据包** | `data/` 文件夹打包的 zip —— 角色卡 / 世界书 / 聊天记录 / 预设一次迁移 |
   | 🎴 **角色卡** | 单个 PNG 或 JSON —— 生成一个工作区 + 带开场白的会话 |
   | 📚 **世界书** | world JSON |

4. 回到「角色」页，点开角色卡即可开聊

> **首次使用建议**：先导入一张卡试聊一轮，确认链路通畅，再导入完整数据包。

# 第二部分：给想深挖的人

## 设计思路与架构取舍

这一节解释**为什么是这样做的**——读它能明白项目的能力边界从何而来。

### 为什么自建运行时，而不是套壳浏览器？

安卓上跑 Node.js 服务有几条路，我们选了最重的一条：

| 方案 | 为什么不选 / 为什么选 |
|---|---|
| ❌ WebView 套一个网页版 ST | ST 是 Node 服务 + 浏览器前端，套壳等于**在手机上再跑一个 ST**，性能与后台存活都不可控 |
| ❌ Termux + 用户手动配置 | 要求用户会命令行；且 Termux 自身受 phantom process killer 困扰 |
| ❌ 云端容器 + 瘦客户端 | 需要服务器与账号，**与「全部本地运行、不上传数据」的承诺冲突** |
| ✅ **自建宿主：把 DSH 运行时打进 APK** | 用户装上即用；数据全在本地；后台靠前台服务保活 |

**代价**：装机包约 122MB（含 Node 二进制 + 运行时 + 依赖），首启需解压约 2.4 万个文件。

### 原生库为什么**不入库**（`jniLibs/*.so`，约 100 MB）

`jniLibs/` 下是 **Node 二进制 + proot + busybox + 依赖库**（14 个 `.so`，实测 100.3 MB）。
**它们全部来自第三方**（Termux 官方源的 deb 包），其中 **proot / busybox 是 GPL-2.0**。

⇒ **本仓库不分发任何第三方二进制**，改为**构建期获取**：

```
node rp-workspace/scripts/fetch-native-libs.mjs
```

- ✅ **好处**：仓库里不含第三方二进制（许可面最干净；GPL 义务的完整分析见
  [THIRD_PARTY_LICENSES.md](docs/THIRD_PARTY_LICENSES.md) §5 —— **本项目 MIT 许可不受影响**）
- ✅ **脚本自带 deb 级 SHA256 校验**：来源链可追溯，上游被替换会**报错而不是静默取用**
- ✅ 首次需联网（或预先放好 `downloads/` 缓存），之后**幂等跳过**（已存在的 .so 不重复处理）
- ⚠️ **代价**：不再是「克隆即可构建」，多一步 —— 构建脚本 **Step 0.1** 会自动检查并给出补齐命令

### 为什么需要 proot？

**背景**：DSH 的进程级沙箱在桌面用 bubblewrap / Landlock / Windows ACL。但安卓上：无 bubblewrap、
5.4 内核无 Landlock（主线 5.13 才合入）、user namespaces 对 app 域不可用 ⇒ **任何受限模式都直接拒绝执行**。

**处置**：分两层
1. **降级层**：识别到无沙箱后端时，返回 `enforcement: "unusable"`，由文件系统边界兜底
2. **真隔离层**：用 **proot**（用户态 chroot，ptrace 拦截系统调用改写路径）包装命令，达到 `enforcement: "full"`

**代价**：
- proot 每条系统调用要过 ptrace（I/O 密集场景开销明显）
- 在**量产 user 固件**上，proot 把 loader 拷到应用缓存目录再 exec，可能被 SELinux neverallow 拦截 ⇒ 探测失败 ⇒ 自动回退到文件系统边界
- ⚠️ **Android 15 起收紧 seccomp，proot 路线会被打断**（`SIGSYS`）。已记录并评估替代方案（见 `docs/C-ANDROID-HARNESS-ASSESSMENT-2026-09-13.md`）

### 安卓平台限制（诚实说明）

安卓不是一个「什么都能跑」的系统。以下是本项目**必须绕开**的平台约束：

| 约束 | 表现 | 我们的处置 |
|---|---|---|
| **无 `bash`** | DSH 的 bash 工具硬编码 `bash -c` ⇒ spawn EACCES | 平台感知改用 `/system/bin/sh`（mksh） |
| **无 `flock(2)`** | 会话写锁抛 `ERR_FLOCK_UNSUPPORTED_PLATFORM` ⇒ **消息发不出去** | 单进程运行时按上游对 browser worker 的同款处置：立即成功 |
| **SELinux 禁硬链接** | 会话日志用 `link()` 原子发布 ⇒ EACCES ⇒ **无法落盘任何会话** | 改 `rename()`（单进程无并发风险） |
| **SELinux 只允许从 `nativeLibraryDir` 执行** | 放在应用目录的二进制无法 exec | 所有需执行的二进制改名 `.so` 放 `jniLibs`（系统解压时保留 exec 位） |
| **phantom process killer**（Android 12+） | **全系统**后台子进程超 32 个即静默 SIGKILL | 前台服务 + 电池白名单；长任务建议开启开发者选项「停用子进程限制」 |
| **无 `zstd` 编码器**（WebView） | 默认压缩的会话日志 WebView 读不了 | 构建期补丁改 `compression: 'none'`（明文 JSONL） |
| **`ripgrep` 不可用** | linux 预编译版是 glibc，bionic 加载不了 | 纯 JS 降级实现（glob 递归枚举 + 逐行正则） |
| **原生模块不可用** | `sharp` / `koffi` / `node-pty` 等含原生二进制 | 平台 stub 替换（可加载但不可用，调用点抛受控错误） |

> 这些补丁**全部可查、幂等、带命中数断言**，集中在
> `rp-workspace/scripts/apply-platform-patches.py` 与 `build-dsht.ps1`。
> 两条路径的补丁集等价性有常驻判据守护（`scripts/audit-build-path-parity.py`），
> 且已接入权威构建路径的前置检查（`build-dsht.ps1` 的 **Step 0.5 门禁前置**——
> 七项常驻审计任一不过即停；另在 **Step 0.6** 有「**官方契约事前探针**」
> `scripts/audit-official-contract.mjs`：构建期校验官方包关键契约的 6 个面，
> `BLOCK` 级破坏即中止构建，把「官方 beta 破坏性变更」从**用户真机撞见**提前到**构建期**；
> 见 `docs/MOBILE-TEST-METHODOLOGY.md` §5.1 与 P-4）。
>
> **设备侧**另有 `scripts/audit-session-integrity.mjs`（会话文件**结构自洽性**审计：
> 按官方 surface 语义校验 `surfaceOp.replace` 的引用完整性 / seq 唯一性 / 行合法性，
> 带 `--selftest` 11 项，退出码 fail-closed）——它是 **P-21**（夹具写操作必须与
> 被测系统内存态互斥）的机器化形态，并作为 M7 旅程的 **J16 收尾校验**常驻执行；
> 见 `docs/MOBILE-TEST-METHODOLOGY.md` §6.5i 与 §6.5j。
>
> **设备侧能力探针**（L2/A1 面，须真机方可执行）：
> - `scripts/ef-keyboard-inset.mjs` —— 软键盘避让（**P-22** 的落地判据）：
>   用 `dumpsys window displays` 的 IME `InsetsSource` 帧作**与页面无关的权威口径**，
>   断言「键盘真的弹出（杠杆）+ 输入区未被遮挡 + 原生真的收到 IME insets +
>   避让走 margin 通道 + **页面视口真的收缩**（终判）+ 收起后判据不恒真」。
> - `scripts/ef-theme-follow.mjs` —— 帧内主题跟随（L2）：断言帧内 `color-scheme`
>   双向跟随宿主主题切换（dark↔light）。
> - `scripts/ef-orientation.mjs` —— 竖屏/横屏适配（L2）：用
>   `adb shell settings put system user_rotation` **真转屏**（并关掉加速度计自动旋转
>   以免被传感器覆盖），断言「五件套在横屏下**仍生效**」（汉堡可见 + 侧栏仍是 fixed
>   抽屉）+ 无横向溢出 + 浮球在视口内 + 转回竖屏幂等 + **O6 夹具安全：系统设置已还原**
>   （读回比对**原值**并计入退出码）。
> - `scripts/ef-font-scale.mjs` —— 系统字号缩放适配（L2）：用
>   `adb shell settings put system font_scale` 切 1.0 / 1.5 / 0.85 三档，先断言
>   **杠杆**（根字号确实随系统变 —— 不传导就是「测不出来」而非「事实否定」，P-17/SKIP），
>   再断言各档无横向溢出、输入区在视口内、五件套仍生效、无「被裁掉又滚不到」的文本、
>   浮球在视口内、**缩小档我方触控目标仍 ≥38px**（这是放大档看不出的风险方向）、
>   还原幂等。**夹具安全**：`font_scale` 是设备全局设置，结束时**必须**还原并校验
>   （S8 永不豁免）。该探针首跑即抓到 P-25（触控规则命中且带 `!important` 却被
