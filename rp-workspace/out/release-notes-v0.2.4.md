# DSH Tavern for Android v0.2.4

主题：**补齐并行产品面收尾**（[GOAL-DSH-ANDROID-COMPLETE](docs/GOAL-DSH-ANDROID-COMPLETE-2026-09-21.md) 的 W-8 系统轻入口 + W-9/W-10 调研收口）——在 v0.2.3「够了设备能力」之上，把系统级入口与调研面一并收齐。

## 本版增量

- **分享 sheet 扩展**（W-8）：以前只能从别的 App「分享」zip 给本 App（ST 数据包迁移）。现在**文本、链接、图片**都能分享进来——浏览器里看到一段话/一个链接，直接分享给 DSH Tavern 即可带进 RP 会话；图片（角色卡头像、参考图）同样。四类内容都落同一个 inbox 并走既有通知链路，前端按类型分流。
- **快速设置磁贴「DSH 局域网」**（W-8）：下拉快捷设置即可开关局域网访问，不必先进 App、等前端加载、再点进设置面板。这正是 LAN 的典型场景——「我不想动手机，在电脑上操作」。切换会重启本地服务让新配置生效。
- **两份调研报告收口**（W-9 / W-10）：
  - [敏感数据落盘调研](docs/W9-DATA-AT-REST-2026-09-21.md)：回答「凭据会不会进会话日志」「Keystore 静态加密开销」「现状威胁模型」三问，**决策为维持现状**（不引入设备级加密），并给出 4 条推翻条件与 2 条可执行建议。核心发现：凭据不进会话日志是**结构上**不可能进（记录结构里没有凭据字段），而非事后脱敏。
  - [插件安装通道调研](docs/W10-PLUGIN-INSTALL-2026-09-21.md)：明确 DSH 插件加载机制的**外部目录注入点**（首选 = 在 profile patch 里把插件 `name` 写成绝对路径，官方会自动转成 `file://`，无需 pnpm），穷举 7 个**不可用**的候选并说明原因，如实标注两个硬缺口（无冲突检测 / 无卸载通道）。

## 修复

- **CI 出包链补全**（v0.2.3 时被 W-1 接入构建链后暴露的三处缺口）：
  1. 工作流从未安装 NDK，而 node-pty 交叉编译需要它 ⇒ 构建必红。已补安装步骤。
  2. 交叉编译需要的 node 头文件（`node_api.h`）只随 Termux 的 nodejs 包分发，而本仓 `downloads/` 不入库 ⇒ CI 净环境缺它。已让原生库获取脚本顺带解出该头目录（与本地同一来源），并做了删除后自愈的负控验证。
  3. 发布 release 资产需要写权限，而默认的 CI 令牌是只读 ⇒ 上传被拒。已按最小授权补 `contents: write`。
